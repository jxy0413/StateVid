# Configuration reference

Configurations are standalone JSON files. Run a configuration from the project root with:

```bash
statevid-train --config configs/bcd_levir_cd.json --output runs/levir_cd
```

## Dataset and task

| Field | Description |
|---|---|
| `task` | `bcd`, `scd`, `bda`, or `cc` |
| `dataset` | Display name recorded with the run |
| `manifest` | Path to the dataset manifest |

Image and annotation paths inside the manifest are relative to the manifest's directory, or its optional `root` directory.

## Model

| Field | Default | Description |
|---|---|---|
| `variant` | `conditional_multiplicative` | State-conditioned multiplicative difference update |
| `depth_factor` | `5` | Encoder residual counts are `(d, 2d, 5d)` |
| `grid_size` | `16` | Spatial size of each learned RGB perception grid |
| `bottleneck_ratio` | `4` | Modulation width is `max(1, floor(C / ratio))` |
| `num_classes` | Dataset-specific | SCD semantic output count, including unchanged ID 0 |
| `pretrained_backbone` | `null` | Optional local X3D-L initialization file |
| `state_update` | `true` | Apply endpoint-guided pre/post state updates |
| `modulation` | `true` | Apply the state-guided difference-modulation residual |
| `modulation_scales` | `[0, 1, 2, 3]` | Zero-based scales where modulation is active |
| `readout` | `role` | Role-aligned features; `mean` and `max` provide shared role aggregation |

`depth_factor` values 3, 5, and 7 give the Small, Default, and Large depth configurations. The feature channels remain `(24, 24, 48, 96)`.

## Training

| Field | Example value | Description |
|---|---|---|
| `epochs` | `100` | Epoch budget when `max_steps` is not set |
| `max_steps` | `null` | Optimizer-update budget; overrides the epoch-derived budget |
| `batch_size` | `8` | Micro-batch size |
| `accumulation_steps` | `1` | Micro-batches accumulated per optimizer step |
| `lr` | `0.0002` | Adam base learning rate |
| `weight_decay` | `0.0001` | Base weight decay |
| `seed` | `42` | Random seed |
| `crop_size` | `256` | Synchronized dense-training crop size |
| `amp` | `true` | Use mixed precision on compatible CUDA devices |
| `eval_every` | `1000` | Validation interval in optimizer updates |
| `eval_batch_size` | `2` | Validation micro-batch size |
| `eval_tile_size` | `null` | Optional native dense-evaluation tile size |
| `workers` | `4` | DataLoader worker processes; the CPU demo uses zero |
| `warmup_steps` | Budget-dependent | Learning-rate warm-up before cosine decay |
| `grad_clip` | `5` | Maximum global gradient norm |
| `pseudo_weight` | `0.0` | Weight for optional cached SCD pseudo labels |
| `pseudo_schedule` | `true` | Warm up and ramp the pseudo-label weight; `false` uses a constant weight |
| `pseudo_warmup_epochs` | `10` | Initial epochs with zero pseudo-label weight |
| `pseudo_ramp_epochs` | `5` | Linear ramp length after pseudo-label warm-up |
| `selection_metric` | Task-specific | Validation metric used for the best checkpoint |

The example BDA configuration uses accumulation two, and caption configurations use accumulation four. Override `--max-steps` on the training command for a shorter run.

## Captions

| Field | Default | Description |
|---|---|---|
| `min_word_freq` | `5` | Keep training words with `count > min_word_freq` |
| `max_words` | `50` | Maximum number of reference words |
| `beam_size` | `3` | Generation beam width |
| `metric_backend` | `builtin` | Lightweight BLEU/ROUGE, or `coco` for the full optional metric suite |
| `include_meteor` | `false` | Include Java-backed METEOR in full-backend validation |
| `image_size` | `256` | Caption image resize size |

DUBAI-CC uses a zero word-frequency threshold. The model's sequence length accommodates both reference words and the start/end tokens.

The base caption evaluator supplies `ROUGE_L` and BLEU-4. Example caption configurations use `ROUGE_L` for validation selection. Install the `caption` extra, set `caption.metric_backend` to `coco`, and set `train.selection_metric` to `CIDEr` to select with the complete metric suite.

| `cc_levir_cc.json` | CC | LEVIR-CC |
| `cc_dubai_cc.json` | CC | DUBAI-CC |

The configurations under `ablations/` are complete JSON files. Change only the intended model setting when comparing variants, while using the same data, seed, optimizer, and training budget.

`demo_bcd.json` is a two-update CPU example for images generated by `scripts/prepare_demo.py`; it uses the default architecture with `32 × 32` image pairs and a micro-batch size of two.
